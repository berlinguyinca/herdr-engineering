# Native CI and reviews

Approved in conversation: integrate Woodpecker and Plannotator into the existing HerdR frontend. Use existing navigation, tokens, outcome tabs and inspectors. Show actual activity, elapsed time, last successful update and connection errors. Never infer progress percentages or a stalled job merely from elapsed duration.

Woodpecker remains execution authority. Keep PAT credentials in a private server-side file/environment, never browser responses. Discover accessible repositories through the user API; collect bounded paginated snapshots in the background with single-flight polling, per-repository errors and last-known results. Pipeline/step details and bounded redacted logs use verified v3.18 API routes. Optional actions require operator role, explicit deployment opt-in and provider permissions. Correlate repository and full revision; project overrides aggregate repositories without using ports as identity.

Plannotator remains review authority. Its local CLI advertises a runtime address and returns a decision receipt. Persist review identity, exact revision, relationships, upstream URL and receipts through the existing PostgreSQL event sink. A host-side launcher connects the actual upstream CLI to HerdR; the web server does not execute arbitrary review commands. Review decisions come from supported upstream results, not fabricated local approvals. Do not invent a separate Planator product: plans/revisions are review subjects and link to missions.

Expose CI and Reviews pages, overview summaries and contextual mission/session links. Current, failed/changes-requested and finished outcomes stay separate. Routine refreshes stay quiet; meaningful status changes use existing event surfaces. Validate provider contracts, cache concurrency/failure, auth boundaries, durable review replay, browser navigation and native visual layout. Live validation must explicitly report rejected credentials or unavailable upstream installation.
