# G5 handoff: week card expansion, filter chips, row details

Branch `feat/wc001-g5-week-card-expand-filter` (worktree herdr-wc001), stacked on G4 / PR #647. Not pushed.

## Behaviour
- `weekCardModel` groups now carry `{key, items (after filter), total (before filter), expanded, shown}`; the model also returns `filter` and `detailIds`. Inputs (in-memory, from `mountOverview`'s data): `weekFilter` (started|finished|open|paused|attention), `weekExpanded` (group keys), `weekDetails` (work ids). Unknown values are ignored.
- Per-group **Show all N / Show fewer** buttons (aria-expanded) beyond the 5-row cap. The cap applies to the filtered list.
- **Filter chips** (aria-pressed buttons, press again clears). Row predicates mirror work-week.js: started = own `started_at` in window; finished = finished with `completed_at` in window; open = running/blocked/review/paused_quota; paused = paused_quota; attention = blocked/review/failed-updated-in-window. Headline counts come from `weeklyActivity`, untouched, so they cannot change. The Unconfirmed group is never filtered and the card says so.
- **Row details**: only WorkSummary fields (lifecycle, coverage, started/completed/updated, evidence kinds and times, mission/session links, a pointer to the session page Terminal button when a pane ref exists).
- **Repository filter: not built.** WorkSummary has no repository field (links only carry mission/session ids); nothing is inferred.
- Focus is restored to the same chip/toggle after the morph redraw. CSS is scoped `.wk-*`; rows wrap so details span the full row at narrow widths. Flag off: card not rendered, nothing touched.
- Existing components reused: `hd-btn` button classes and the attention card's `aria-expanded` "Show all N / Show fewer" pattern. No new framework.
