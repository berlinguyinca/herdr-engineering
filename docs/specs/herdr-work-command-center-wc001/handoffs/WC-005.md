# WC-005 handoff

## Audit: what relationship data exists (read this first)
- Project item (`herdr_engineering/github.py::_project_item`, served by `/api/v1/github/projects`): `item_id`, `type` (ISSUE | PULL_REQUEST | DRAFT_ISSUE | REDACTED | UNKNOWN), `repository` (nameWithOwner), `number`, `url`, `state`, `title`. Redacted/draft items lack repository/number.
- Herdr-side relationships that ARE source-backed: only mission -> pull request records (`repo.list_pull_requests(mission_id)`, fields `repository`, `number`), surfaced per mission by `GET /api/v1/missions/:key/story` (refs kind `pr`) and in `mission_outcome.assemble` (`prs`). PR trail (`pr_trail.py`) maps PR -> sessions per PR on demand.
- NOT available at list level: `outcome_summaries` (what `/api/v1/mission-outcomes` returns to the browser) carries only `repository`, no `prs`. Mission/session list records carry no issue or PR numbers. No issue -> mission relationship exists anywhere.
- Consequence (LOUD): nothing the board view currently loads can verify a link. Building refs would need either an N+1 `missionStory` fan-out per poll or a new bulk endpoint; both were out of scope (no new endpoints). So **in the real app today, every card resolves to `none` and no "Open in Herdr" link appears.** This is the honest outcome; the resolver and render are ready for when a bulk source exists.

## Changed
- `packages/board-links.js` (new): pure `resolveBoardLink(item,{refs,refsFailed})` -> `{state:'verified'|'none'|'ambiguous'|'partial', target?:{kind,id,href}}`. Verified only if exactly one distinct mission/session ref matches repository (case-insensitive `org/app` or `github.com/org/app`; other hosts never match) + integer number + type (issue vs pr). Title/free text never used. Duplicates of the same ref collapse; two distinct targets = ambiguous. href only via `entityHref` (over-long/unlinkable id -> none). REDACTED, or issue/PR missing repository/number, or `refsFailed` -> partial. `refs` null/absent (no source wired) -> none.
- `packages/github-projects-view.js`: `renderProjectCard/Row(entry,resolved)` add `<a data-herdr-link>Open in Herdr</a>` only for verified, `Herdr data partial` note for partial, nothing otherwise; external link unchanged. `mountGithubProjects` takes options `herdrRefs` (default null) and `herdrRefsFailed`; `app.js` is NOT changed, so no refs are wired. No new endpoint, credential or write call.
