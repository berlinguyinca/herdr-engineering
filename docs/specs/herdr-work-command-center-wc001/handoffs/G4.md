# G4 handoff: user-set time zone and week start

Branch `feat/wc001-g4-timezone-week-start` (worktree herdr-wc001), stacked on G3 / PR #646. Not pushed.

## Storage decision (audit)
- `/api/v1/inspector/.../preferences` (api.py ~3933, 5413, 5492): agent-inspector display prefs (global/per-session), not general dashboard prefs; no tz/week fields. Not honest to overload.
- Assistant `notifications.timezone` (api.py ~4461): server config for reminders, one value for the deployment, not per user. Not suitable.
- Client pattern: overview-view.js already persists the Overview layout in localStorage (`herdr.overview.layout.v1`, sanitized, try/catch); other views (ci-observability, ci-health, collab) do the same. Reused that pattern with its own key `herdr.overview.week.v1` (a separate key so "Reset layout" does not erase it and the layout sanitizer is untouched).
- Consequence: per browser, not per user; not synced. No new table, endpoint or service.

## Behaviour
- `sanitizeWeekPreferences / loadWeekPreferences / saveWeekPreferences` (overview-view.js): tz validated with Intl, week start in monday|sunday|saturday; any failure of storage gives defaults. `userTimeZone` now falls back to the browser zone (was UTC) for an unknown zone; UTC only if the browser zone is unusable.
- `weekWindow` already supported weekStartsOn 0..6 with DST-safe half-open windows; unchanged. Card passes it, the weekly-events window uses the same zone/start, and a change re-reads it (abort + sequence guard).
- Card shows the zone and week start in use (selects plus the note "Week of <date> (zone), week starts X").
- Default (nothing stored) is unchanged: browser zone, Monday. Flag off: no card, controls and storage are never touched.
