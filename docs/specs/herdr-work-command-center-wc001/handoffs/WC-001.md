## Rules implemented
Mission owns a session only via `associatedMission` (explicit). Unresolved mission reference (unknown or ambiguous) -> standalone, `unassociated: true`, coverage `partial`. Same bare session_id on several hosts, or host-less session with an ambiguous id -> never joins. No title correlation. Mission lifecycle comes only from the mission (agent finish never completes it). Non-current (stale/disconnected/recorded-only) -> `unconfirmed`. Progress only through `measuredProgress`.

## Data-contract diff vs DATA-CONTRACT.md
- Added `unassociated: true` on standalone session items (contract says "visibly unassociated" but has no field).
- `progress.basis` is the constant `'measuredProgress'`: the existing function returns only `{percent,label}`, not its branch; label carries the evidence. `measured_at` = projection `activity_snapshot_at`/`snapshot_at`.
- `lifecycle`: `review` never produced (no verified source); `paused_quota` only when mission status contains QUOTA; `blocked` from health blocked/stalled.
- `source`: only `mission` and `session` (no github_item/ticket yet). `project_ref`, `next_action` not populated.
- `coverage` for a mission is `complete` only when live and current, else `unconfirmed`; `partial` when any ambiguity touched it. Unreferenced standalone session: `unconfirmed`.
- `pane_refs` include only sessions with host_id+herdr_session+terminal_id; `pane_id` optional. Stale-pane refresh is not handled here.
- `completed_at` for missions is recorded `completed_at`, else recorded `updated_at` when outcome is finished (approximation; verify in WC-004 weekly counts).
- Weekly counting, time zone/DST: out of scope here.
