# G1 handoff: weekly lifecycle history

Branch `feat/wc001-g1-weekly-history` (worktree herdr-wc001), 4 commits on top of aa054f27. Not pushed.

## Audit findings
- Durable timestamps: missions get `MissionCreated`/`MissionStarted` (written when the control plane first sees the mission, not at the true start), `MissionStageChanged`/`MissionUpdated` (terminal stages complete/failed/cancelled), inferred `MissionOutcome`; sessions get `SessionStarted`/`SessionUpdated{status}`.
- Store: in-memory `_events` per (entity_type, entity_id) plus global `_event_order`; a best-effort sink writes Postgres `fabric_events` (failures swallowed, no retry); `bridge.load_into` rehydrates at startup.
- Retention: `apply_retention` (30-day) is called only from tests; production runs only `sweep_token_usage` (token usage). Mission/session events are not pruned in production.
- Paused-quota: no Python code emits it; only the client derives it from a status matching /quota/.
- Can `historyComplete` be truthfully true? No, not anywhere in this build. Emission is not provable (first-sight starts, best-effort sink, never-ending work has no finish). `EMISSION_PROVEN = False` in `work_weekly.py`; server `coverage.complete` is constant false with `reasons`. The client shows "complete" only when the server returns complete:true, untruncated, horizon <= window start; only JS/stub tests inject that.

## Contract diff
New `GET /api/v1/work/weekly-events?since=&until=&limit=&after=` (additive, read-only):
- Half-open [since,until), RFC3339 with offset; span <= 31 days; limit default 200, max 500; opaque `after` cursor; repeated/invalid params -> 400.
- Auth identical to `/api/v1/events` (global viewer check: 401 without/with wrong key; reader and writer 200). 404 when work_center_v1 is off or any other sub-path.
- Response: `{window, events:[{kind: started|finished|failed|paused_quota, work_id, source, entity_id, occurred_at, evidence:{ref,event_type}, mission_key?, host_id?}], next_cursor, coverage:{complete,horizon,truncated,reasons}}`. Deduped per (work item, kind), earliest event wins; no payload content or titles.
- Client: `HerdrClient.weeklyEvents()`; `weeklyActivity(..., serverHistory)`; one-shot read in `mountOverview` (flag on), aborted on dispose. Sessions with a `mission_key` are owned by the mission (no double count on reassociation). Conflicting timestamps degrade to partial.
