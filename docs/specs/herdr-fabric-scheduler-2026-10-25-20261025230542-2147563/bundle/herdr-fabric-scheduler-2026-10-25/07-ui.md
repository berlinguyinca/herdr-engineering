# Phase 7 — production UX/UI specification (reuse current Herdr design)
Do NOT rebuild dashboard shell or introduce a disconnected admin SPA. Audit current components/routes/design tokens and extend existing Machines/Fleet/Agent views; preserve responsive dark terminal style and accessibility. Existing `Automatic agents` switch migrates to mode picker without silently enabling excluded hosts. Read-only previews do not mutate policy.

## A. Fleet overview
Add "Scheduling" view/tab inside existing Fleet: headline cards `Eligible hosts`, `Unavailable`, `Queued agents`, `Running agents`, `Reserved CPU/RAM`, `Placement p95`, `Host pressure alerts`; time-series for aggregate pressure, queue duration, placements/min, rejections, and completed work; user can filter site, owner, project, workload class and time window. Live updates using existing event stream; stale telemetry visually distinct from zero load.

## B. Host cards/details
Host name, location/site, stable identity (masked), runtime families, policy badge/selector, health/freshness, CPU PSI/usage, RAM available/reserved, IO PSI/free disk, GPU diagnostics, active and queued agents, headroom score, throttling warning. Selecting a host shows resource timeline, actual running agents, reservations, exclusion rules, last telemetry, and actions: policy change, drain, return to auto, explicit manual launch, inspect audit. Require confirmation for disable/drain and optimistic concurrency on policy writes. Mac permanently displayed as `Manual only` until user expressly authorizes policy change.

## C. Agent launch modal
Default `Placement: Automatic (recommended)` with chosen host preview and "Why this host?" explain list; alternate `Choose host manually` shows all hosts with health and reason unavailable; advanced options: workload profile, resource envelope, project priority, affinity, preferred site, maximum queue time. Never auto-select Mac when manual override is not engaged. If no host qualifies, show queued position/reasons and `Edit constraints`/`Cancel`.

## D. Placement explanations
Every decision links to structured `selected`, `eligible`, `rejected` lists, reason codes and measured values at timestamp, reservation request ID, policy version and who requested. `AutoSpec → implementer → reviewer` graph shows physical host badge on every agent and cross-host edges; moving agent updates host badge without changing agent identity. Context menu "Why here?", "Pin here" (authorized explicit choice), "Drain host", "Move when safe" (only checkpoint-capable) and "Retry queued". Audit timeline correlates decisions with load.

## E. Simulator
Interactive panel: historical replay period 24h/7d/30d, candidate policy weights, host exclusions, workload count/types; plot simulated host load, queue p50/p95, over-capacity attempts, projected completion and schedule/actual comparisons with confidence warnings. Dry-run only, no scheduler state mutation.

## Accessibility/responsive
Keyboard operable, ARIA for host policy/select, clear red/amber/gray distinctions with text (not color alone); adapt 390px/mobile, 1440 desktop and 4k wide layout; virtualize large host/agent lists, persist filters in existing routing pattern, avoid overflow. Do not expose host topology or secrets to public collaboration guests. Error states, empty states, loading/skeleton, offline/stale, reconnect, optimistic rollback.

## Visual acceptance
Playwright screenshots at mobile/tablet/desktop/4k, keyboard and contrast checks, policies survive refresh, Mac blocked, graph links correct and telemetry freshness readable.
