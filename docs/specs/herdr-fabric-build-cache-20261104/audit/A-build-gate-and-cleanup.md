## 1. build-coordinate (herdr_engineering/build_coord.py, 327 lines)
- No "states" machine. A slot is just free/held (flock). `BuildGate.status()` (build_coord.py:192-218) reports `{slot, held, holder}`; `held` is probed by a non-blocking LOCK_EX attempt, NOT by the payload text (stale payloads stay after release).
- Dir: `_default_state_dir()` = `$HERDR_ENGINEERING_STATE` or `~/.local/share/herdr-engineering/state`, + `/build-gates` (:41-44). (Module docstring :21-22 says `~/.cache/herdr-engineering/build-gates/` -- stale, wrong.)
- Files: `gate.{0..N-1}` slot locks (:90-91), `build-maintenance.lock` (shared lock, :313), `telemetry.jsonl` (append-only, :175-190). `build-cleanup.json` (cleanup status) is in the same dir.
- Slot lock: `_try_acquire` opens gate.N O_RDWR|O_CREAT 0644, `flock(LOCK_EX|LOCK_NB)` (:110-112), writes JSON payload {pid, host, slot, start, cmd[:8]} via ftruncate/write/fsync (:117-129), `set_inheritable(fd)` so the flock survives `os.execvp` (:131, :284). Lock released by kernel when child exits. Non-POSIX returns (None, index) = no gating (:107).
- Maintenance lock: `run_gated` (:300-327) takes `LOCK_SH` on build-maintenance.lock (0600, O_NOFOLLOW) BEFORE slot acquisition, inheritable across exec, even on bypass-on-timeout. Cleanup takes LOCK_EX.
- Identity/dedup: NONE. No build id, no command/workspace fingerprint, no dedup of identical builds. Only `pid` (becomes child pid after exec), host, slot, start time, first 8 argv. Two agents building the same workspace each take a slot.
- What it records: slot payload (ephemeral, overwritten next holder) + telemetry.jsonl `contention` events only (ts, host, slots, max_load, busy_pids, load_core; :160-166). No start/finish/exit-code/duration/cache record.
- Auto slots: `_default_slots()` = `max(2, min(4, cores-4))` (:59-68). Slots tried in index order 0..slots-1 (:148). CLI: `slots = args.slots if not None else _default_slots()` (cli.py:2743-2745). Load backoff: sleep 0.5 while 1-min loadavg/cores > max_load (:145-147; max_load<=0 disables). CLI default max-load 1.5 (cli.py:~69); pi extension passes 3.0.
- **Contradictory docs statement (docs/build-gate.md)**: lines 137-140 say slots auto = `max(2, cpu_cores-4)`, "20 on 24 cores"; lines 179-183 say conservative: two on small hosts, at most four. **The cap-at-4 statement is TRUE**: source `min(4, ...)` (build_coord.py:67-68) and tests `test_default_slots_scales_with_cores` / `test_default_slots_cap_high_core_hosts` (tests/test_build_coord.py:32-46). Same stale "max(2, cores-4)/20 on 24 cores" text also in cli.py `--slots` help (~line 66-67), the docstring of deploy/pi-build-gate/build-gate.ts:21-22, :68, and docs/build-gate.md:208-214 note ("auto default cores-4 ... 20 on 24 cores"). Also docs line 146 "compound commands are left ungated" is only loosely true (see s3).

## 2. build_cleanup.py (295) / build_maintenance.py (83)
- Deletes: ONLY Cargo `target/` dirs, under explicit configured roots, same user, same device, no symlinks/special files, no nested Cargo.toml/.git inside (`_discover` :91-119, `_inspect` :122-148). Target recognised by parent `Cargo.toml` + one of `.rustc_info.json`, `debug/.fingerprint`, `release/.fingerprint` (:109-111). Prunes .git, node_modules, .venv, venv, .cache, __pycache__ (:23); depth <=6; 500k entry cap. Never deletes sccache dirs, ~/.cargo, toolchains, worktrees.
- Policy: validates finite, `0<=low<high<=100`, `min_age_hours>=24` (hard floor, :193). Triggers only if root fs usage >= high_water (85%) (:229); deletes oldest first until <= low_water (80%) (:256-263). Candidate must have newest mtime anywhere inside older than cutoff (:244). `_untracked` = `git ls-files -- target` empty (:151-157; non-git => preserved).
- Active detection: (a) exclusive flock vs. coordinated builds; (b) `_process_paths` (:62-88) scans /proc of same-uid processes: cwd, exe, all fd symlinks; any path under `target.parent` => "active project" (:265, rechecked :276-279). Unreadable /proc entries: if ancestry reaches a same-user `herdr` process (`_managed_process` :29-59) -> raise (abort, fail closed); unknown ancestry raises; else ignored. Builds outside the gate are protected only by this heuristic (docs/build-cleanup.md:267-276 admits not race-free).
- Exclusive lock: `run_once` opens `<state_dir>/build-maintenance.lock` (O_NOFOLLOW 0600) and `flock(LOCK_EX|LOCK_NB)`; on BlockingIOError returns `status:"busy"` without writing status (:202-209). Held for whole sweep. New coordinated builds block on LOCK_SH meanwhile.
- TOCTOU exposure: gated builds are race-free (lock). Ungated builds: window between `_process_paths` and `shutil.rmtree` (:276-287) -- a build started in between (cwd under target.parent) is not seen; mtime recheck helps only if files already written. `state_dir.is_relative_to(target)` guard :233. `shutil.rmtree` fd-based (symlink-attack safe, asserted :285). Break on first error (:295). `_sweep` computes `active` once pre-loop then refreshes per candidate. `reclaimed_bytes` = observed free-space delta (noisy).
- Dry run: `run_once(dry_run=True)` does full validation incl. rechecks, appends `would_remove`, no delete (:280-282); CLI `--dry-run`. Note dry run still writes build-cleanup.json (:213).
- Status file: atomic `build-cleanup.json` via mkstemp+replace (:168-176). `herdr-eng build-cleanup status` prints it (build_maintenance.py:352-355).
- Schedule: NOT timer/cron. A systemd **user service** `scripts/herdr-eng-build-cleanup.service` (ExecStart `herdr-eng build-cleanup watch`, Nice=19, IOSchedulingClass=idle, Restart=on-failure) running a loop `watch()` (build_maintenance.py:329-342) every `interval_seconds` (default 900) that runs only while a same-user `herdr server` process exists (`server_running` :309-326). Install: scripts/build-cleanup.sh; fleet: ansible/tasks/build-cleanup.yml (reads host config via venv python, enables/restarts unit only if `build_cleanup.enabled is True` and non-empty roots; else stops it :301-342). Config defaults config.py:29-36 (`enabled: False`, roots [], 900, 85, 80, 24). `watch` returns "disabled" unless enabled (:370-372); `run` works regardless.
- CLI: cli.py:47-54 `build-cleanup {run,watch,status} [--root] [--dry-run]`; dispatch cli.py:2769-2771 -> build_maintenance.command.

## 3. Pi build-gate (deploy/pi-build-gate/build-gate.ts, 114 lines)
- Hooks `tool_call` for `bash` only (:96-97). Disabled if `HERDR_BUILD_GATE_DISABLE=1` or `herdr-eng` not on PATH at load (:88-94).
- Intercepts: command (trimmed) matching `^cargo\s+(check|build|test|clippy)\b` AND flags `--workspace|--all-targets|--tests|--all-features` (:35-36, :80); OR `^(?:npx\s+)?tsc\b` (:39, :81). Anchored at start: `cd x && cargo check --workspace`, `FOO=1 cargo ...`, `cargo +nightly ...`, `npm run build`, `cargo nextest`, `rustc`, plain `cargo build` / `cargo test` (no heavy flag) are NOT gated. `-p foo` checks ungated.
- Compound handling: none. Whole string is rewritten by prefixing: `<herdr-eng> build-coordinate [--slots N] --max-load M --wait W --bypass-on-timeout -- <original cmd>` (:110-112). A command starting with cargo/tsc but followed by `&& other`/`|`/`;` is gated only for the first simple command (shell splits); command quoting is not escaped.
- Passes: `--slots` only if HERDR_BUILD_GATE_SLOTS set (:71-76); `--max-load` default 3.0 (env HERDR_BUILD_GATE_MAX_LOAD); `--wait` default 900 (HERDR_BUILD_GATE_WAIT); always `--bypass-on-timeout`.
- Env it sets: NONE (it reads env only; does not inject RUSTC_WRAPPER/CARGO_TARGET_DIR/etc.). No cache awareness.
- Install: deploy/pi-build-gate/install.sh; fleet via ansible/tasks/pi-build-gate.yml (copies to ~/.pi/agent/extensions/build-gate.ts). Skill skills/build-gate/ (scripts/status.sh).
- Only pi is wrapped; claude/codex/opencode are not (docs claim "any agent" for the CLI only).

## 6. Hazards for extending
1. Load guard loop (build_coord.py:145-147) `continue`s before the deadline check (:168), so `--wait` is NOT honored while load/core stays above max-load; with bypass-on-timeout the build can hang indefinitely under sustained load. Existing bug.
2. Lock-order contract: build must hold maintenance LOCK_SH for entire life, including bypass. Any new wrapper (sccache server, lease renewal process) that forks and drops the fd, or a detached daemon, breaks cleanup safety. exec model means no post-build hook point: wrapper is replaced by child, so recording build end/exit code/duration requires changing from exec to fork+wait (which changes fd inheritance, signal forwarding, pid semantics in payload and status).
3. Slot count/naming is shared by callers with different `--slots`; `gate.N` filenames are parsed by monitor-fabric-gateway.sh; state dir must be identical (HERDR_ENGINEERING_STATE) for gate and cleanup.
4. flock is host-local and fails/behaves differently on NFS/FUSE (see logfile_lock.py fallback pattern); fencing/epochs need a durable store, not flock.
5. Cleanup only knows `target/` dirs by Cargo.toml adjacency; if CARGO_TARGET_DIR is redirected to a shared dir or sccache local dir, cleanup will neither see nor protect it, and `state_dir.is_relative_to(target)` guard / "Cargo.toml inside target" rejection apply.
6. Process-scan protection is /proc based, Linux-only; `_managed_process` raises (aborts whole sweep) on ambiguity; changes to herdr process naming break it.
7. Docs/code drift already present: slot-count text (s1), module docstring dir path, CLI help "20 on 24 cores", docs/build-gate.md "any agent". Fix these when touching.
8. Pi extension prefix-regex gating misses env-prefixed and `cd &&` commands; injecting RUSTC_WRAPPER there would only affect gated commands. Command string is concatenated unescaped.
9. Telemetry file is unbounded append, no rotation. Dry-run overwrites last real build-cleanup.json.
10. Ansible fleet checks use checksum/fingerprint of build-gate.ts (tests/test_fleet.py fixtures, ansible/tasks/fleet-fingerprint.yml); editing the .ts changes fleet fingerprints. Tests in tests/test_cleanup_deploy.py assert ansible task text (ordering after package provisioning, never overwriting policy).
