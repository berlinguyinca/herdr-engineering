# P08 — Activity subscriptions, attention and automations

**Depends on:** previous gated phases; see README dependency graph

## Deliverable and implementation contract
Extend existing attention inbox and event store rather than building new notification center. Subscriptions for CI failures, PR updates, mission result, artifact version, review needed, external email, service outages and scheduler blockage. Correlate to project/issue/task/work graph, suppress duplicates and unhelpful chatter. Severity + digest/snooze/acknowledge shared across terminal/WebUI/Rakazo. Automation runbooks must use same task/action broker and policy gates; configure low-risk autopilot for bounded CI fixes while avoiding silent production-impacting merges. Do not spam individual agent steps; one meaningful status per parent task. Gate: 100 duplicate event replays produce one actionable item, no missed critical approvals, no unauthorized automation.

## Required workflow
1. Re-audit relevant code and open PRs; record existing features and exact file paths.
2. Write/update schema and migration plan before implementation; change only owned domains.
3. Implement in unique worktree/feature branch; use existing conventions and tests.
4. Update docs, release notes and rollback/feature flags where relevant.
5. Run focused and repository standard test suites, security and compatibility cases.
6. Add file/command evidence to `evidence/P08-RESULT.md`; label completed, partial or blocked truthfully.
7. Stop if acceptance gate fails. Do not silently skip, mark completed or advance.

## UX contract
Default shows purpose, human-readable progress, next needed action and resulting deliverables. Verbose logs only on expand; no unnecessary user prompts, notifications or manual model selection.
