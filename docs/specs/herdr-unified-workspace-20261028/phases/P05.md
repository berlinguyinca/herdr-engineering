# P05 — Teams, task delegation and skill execution

**Depends on:** previous gated phases; see README dependency graph

## Deliverable and implementation contract
Define reusable team templates (planner, implementer(s), independent reviewer, optional Rakazo coordinator) without permanently pinning instances to hosts. Room/team can submit tasks through Pi authoritative mission admission, with bounded budgets, explicit role, deadline, allowed actions, reviewer separation, task dependencies and lease/fencing. Skills registered via existing Pi skill system; room-triggered skills generate audited execution with artifacts. Prevent messages from auto-becoming shell instructions; task must originate from authorized actor/action broker. Support `/assign`, `/tasks`, `/skill`, `/session attach`, steer, cancel and safe retries. Session migration and host placement via fabric scheduler (respect exclusions/manual-only Macs), record lineage. Gate: assigned task executes once across retry/crash; independent review enforced; aborted execution does not leak privileges; task result links back to room/project/issue.

## Required workflow
1. Re-audit relevant code and open PRs; record existing features and exact file paths.
2. Write/update schema and migration plan before implementation; change only owned domains.
3. Implement in unique worktree/feature branch; use existing conventions and tests.
4. Update docs, release notes and rollback/feature flags where relevant.
5. Run focused and repository standard test suites, security and compatibility cases.
6. Add file/command evidence to `evidence/P05-RESULT.md`; label completed, partial or blocked truthfully.
7. Stop if acceptance gate fails. Do not silently skip, mark completed or advance.

## UX contract
Default shows purpose, human-readable progress, next needed action and resulting deliverables. Verbose logs only on expand; no unnecessary user prompts, notifications or manual model selection.
