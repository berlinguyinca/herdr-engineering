# P03 — Artifact registry and provenance

**Depends on:** previous gated phases; see README dependency graph

## Deliverable and implementation contract
Integrate existing Artifact Registry APIs and RustFS as canonical storage. On every artifact-producing Pi task/skill, register artifact metadata and immutable content hash/version, record origin room/task/issue/project, parent artifact version, execution session, agent/model, prompt/skill revision, repository commit and inputs (with privacy-sensitive fields redacted). Two-phase publish pattern: upload staged binary, create metadata record, link graph edges, commit/mark available; reconcile failed stages and duplicate events. Support PDFs, images, Markdown, DOC/DOCX, spreadsheets, presentations, HTML, JSON, plot data, logs and URLs via typed renderers and safe previews. Add `/artifact show|versions|diff|link|search|publish|share` in CLI/Pi extension as adapter, not authoring via WebUI. WebUI gallery searchable by project/issue/task; version history, comments/annotations, approvals, immutable share links with TTL/revocation, guest rights and public opt-in. Never expose unauthorized artifacts through email or room mentions. Gate: ten artifacts from two agents survive restart, rename and session deletion; accessible from project/issue/task and source provenance; reconciliation corrects simulated crash.

## Required workflow
1. Re-audit relevant code and open PRs; record existing features and exact file paths.
2. Write/update schema and migration plan before implementation; change only owned domains.
3. Implement in unique worktree/feature branch; use existing conventions and tests.
4. Update docs, release notes and rollback/feature flags where relevant.
5. Run focused and repository standard test suites, security and compatibility cases.
6. Add file/command evidence to `evidence/P03-RESULT.md`; label completed, partial or blocked truthfully.
7. Stop if acceptance gate fails. Do not silently skip, mark completed or advance.
