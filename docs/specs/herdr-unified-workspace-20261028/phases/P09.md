# P09 — Reliability, threat model, accessibility and rollout

**Depends on:** previous gated phases; see README dependency graph

## Deliverable and implementation contract
E2E scenario across two hosts plus browser: create team/room, task, two agents, independent review, artifacts and email approval, reconnect, crash replay, restore from backup, revisit old project. Chaos tests for partial artifact publish, dropped socket, reordered event, expired token, concurrent updates, ACL revoke during stream, compromised agent prompt, host migration, stale approval and ambiguous email send. Performance/load tests with large team graphs and high-volume events. Observability trace IDs across HCN->Pi->artifact->Rakazo, metrics for effectiveness and queue latency; sensitive logs redact tokens. Security review/XSS/sandbox preview/SSRF checks. Feature flags for per-user rollout with dark-launch migrations; documented rollback, repair command, runbook and backup restore check. Capture measured UX: time-to-first-task, interruptions per goal, artifact retrieval success, novice task completion. Gate: all phases signed off, compatibility and migration tests green, operations can revert frontends safely.

## Required workflow
1. Re-audit relevant code and open PRs; record existing features and exact file paths.
2. Write/update schema and migration plan before implementation; change only owned domains.
3. Implement in unique worktree/feature branch; use existing conventions and tests.
4. Update docs, release notes and rollback/feature flags where relevant.
5. Run focused and repository standard test suites, security and compatibility cases.
6. Add file/command evidence to `evidence/P09-RESULT.md`; label completed, partial or blocked truthfully.
7. Stop if acceptance gate fails. Do not silently skip, mark completed or advance.

## UX contract
Default shows purpose, human-readable progress, next needed action and resulting deliverables. Verbose logs only on expand; no unnecessary user prompts, notifications or manual model selection.
