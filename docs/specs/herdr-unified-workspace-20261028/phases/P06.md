# P06 — Team-first WebUI and persistent visual map

**Depends on:** previous gated phases; see README dependency graph

## Deliverable and implementation contract
Refactor home default to small "Your teams" list/cards + actionable Attention, not fleet charts. In team page, two principal views: Conversation and Team Map. Conversation shows plain language, one parent task card with milestones, artifact previews and review actions. Team Map reads the persistent Work Graph; explicit node/edge meanings (coordination/delegation/dependency/produced/reviewed), node filters and accessibility textual fallback. Group by project -> issue -> task -> deliverables, collapse noisy execution events by default. Live state overlays separated from historical immutable edges; old work remains browsable. Persist graph layout independently of graph data; personal overrides; deterministic auto-layout for new nodes; auto-position incrementally without moving existing groups. Click task/agent/artifact to open inspector and deep-links to existing CI/host/model/review views. Do not fabricate percent completion; use milestone counts or clear qualitative labels. Gate: novice completes one workflow with no documentation or slash command; graph/timeline/gallery agree on artifacts and relationships; large graph remains performant.

## Required workflow
1. Re-audit relevant code and open PRs; record existing features and exact file paths.
2. Write/update schema and migration plan before implementation; change only owned domains.
3. Implement in unique worktree/feature branch; use existing conventions and tests.
4. Update docs, release notes and rollback/feature flags where relevant.
5. Run focused and repository standard test suites, security and compatibility cases.
6. Add file/command evidence to `evidence/P06-RESULT.md`; label completed, partial or blocked truthfully.
7. Stop if acceptance gate fails. Do not silently skip, mark completed or advance.

## UX contract
Default shows purpose, human-readable progress, next needed action and resulting deliverables. Verbose logs only on expand; no unnecessary user prompts, notifications or manual model selection.
