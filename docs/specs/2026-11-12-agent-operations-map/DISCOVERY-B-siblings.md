## 1. Herdr runtime (the real tool)

- Installed: `$HOME/.local/bin/herdr`, v0.9.1, protocol 22, server running (`herdr status`). Upstream: `herdrdev/herdr` (Apache-2.0; also `herdrdev/herdr-app`, `herdr-core`). Docs index: https://herdr.dev/llms.txt (stable is 0.9.5, local is behind; re-check APIs on upgrade).
- Not `ogulcancelik/herdr` as spec guessed; plugin cookbook is `ogulcancelik/herdr-plugin-examples`. Community plugins seen via `gh search repos herdr`: persiyanov/herdr-reviewr, hhdebb/herdr-radar (agent activity sidebar, MIT; closest prior art), dcolinmorgan/herdr-remote, eliasstravik/shepherdr, 0cv/herdr-mobile-relay, nikok6/herdr-mirror. Not inspected beyond metadata.
- Plugin API (docs: `.../v0.9.5/docs/next/website/src/content/docs/plugins.mdx`, `socket-api.mdx`, `add-herdr-support.mdx`):
  - Manifest `herdr-plugin.toml`: `id, name, version, min_herdr_version`, `[[build]]`, `[[startup]]` (one-shot, not supervised daemons), `[[actions]]` (contexts workspace/global), `[[events]] on=<event>`, `[[panes]]` (placement overlay|popup|split|tab|zoomed, runs any argv = a TUI process), `[[link_handlers]]`. Lifecycle: `herdr plugin install owner/repo[/subdir]` (git clone, build, register), `link <dir>` for dev, `update`, `enable/disable`, `uninstall`, `config-dir`, `log list`. No native non-terminal plugin UI in v1: a plugin cannot draw web UI inside Herdr; only terminal panes. No sandbox; runs as user.
  - Env injected: `HERDR_SOCKET_PATH, HERDR_BIN_PATH, HERDR_ENV=1, HERDR_PLUGIN_ID/ROOT/CONFIG_DIR/STATE_DIR, HERDR_PLUGIN_CONTEXT_JSON, HERDR_PLUGIN_EVENT(_JSON)`, plus WORKSPACE/TAB/PANE ids.
  - Hook event names (from `herdr api schema --json`): `pane.agent_detected, pane.agent_status_changed, pane.created/closed/exited/focused/moved/updated, pane.output_matched, tab.*, workspace.created/updated/renamed/moved/closed/focused, worktree.created`. `workspace.metadata_updated` is subscriber-only (no plugin hook).
  - Socket API: `events.subscribe` / `events.wait` (long-lived line-JSON stream; no durable history; `events_lost` error means resubscribe + `session.snapshot` reconcile), `session.snapshot` (CLI: `herdr api snapshot`), `agent.list/get/read/wait/prompt/start`, `pane.read/send_text`, `pane.report_agent`, `pane.report_agent_session`, `pane.report_metadata`, `workspace.report_metadata`. Schema: `herdr api schema --json` (schemas: event, request, subscription_event, success_response).
  - Agent record fields: `agent, agent_status (idle|working|blocked|done|unknown), cwd, display_agent, name, pane_id, tab_id, workspace_id, terminal_title, title, state_labels, tokens, agent_session{source,agent,kind,value}, revision, state_change_seq`. No model name or context percent is first-class.
  - `pane.report_metadata` / `workspace.report_metadata`: display-only `tokens` map (<=16 keys per report, <=32 retained, TTL, per-key patch) e.g. `{"model":"opus"}`. This is the sanctioned way to publish model/context/room/task into Herdr sidebar rows `$name` without owning lifecycle. Good fit for Agent Ops "model" and "ctx%" tokens.
  - Machines: `--machine <label>` forwards API commands to saved SSH machines (ids are per-server; two hosts can both have `w1:p1`).
- Integrations installed locally (`herdr integration status`): pi v9, claude v10, codex v8, opencode v12, hermes v5; others not installed. Claude hook script `~/.claude/hooks/herdr-agent-state.sh` handles only the `session` action and reports state to `$HERDR_SOCKET_PATH` (python socket client, `source="herdr:claude"`).
- Existing plugin: `herdr.cp-feed` (local, `~/.local/share/herdr-cp-feed-plugin-releases/ci-reviews-20261020`, files `emit.js enrich.js git-metadata.js snapshot.js`). Hooks `pane.agent_detected, pane.agent_status_changed, pane.closed, pane.exited, workspace.*`; maps machine->host, workspace->mission, agent pane->session; POSTs to control-plane `POST /api/v1/ingest` (URL from `<config>/cp-url`, env `HERDR_CP_URL`, default `http://dev.lan`). Best-effort, never blocks Herdr. This is the existing collection pipeline to extend (spec: do not build a second bus).
- Public `berlinguyinca/herdr-dashboard`: does NOT exist (`gh repo view` fails). The dashboard is `~/IdeaProjects/herdr-engineering/packages/*.js` (vanilla JS views: `topology-view.js, team-map-view.js, collab-team-rooms.js, handoffs-view.js, task-drift-view.js, mission-live-view.js, session-workspace.js, event-history.js, refresh-bus.js, motion.js/css`, plus `herdr-design-system`, `herdr-web-client`, `herdr-web-components`) served by `herdr_engineering/control_plane/` (Python; `api.py`, entities session/mission/host, `artifact_room_access.py`, `workspace_contracts.py`). ## 3. Contracts worth reusing

- Handoff v2 (herdr-handoff/schemas/handoff-v2.schema.json): required `handoff_id, schema_version, state, source, target, context`; optional `created_at, updated_at, workspace, links, report, artifacts, memory_context, redaction, history`. State enum: `draft, queued, claimed, accepted, in_progress, completed, rejected, cancelled, expired, failed`. Directly maps to a handoff edge's animation state in the map.
- Artifact registry (herdr-artifacts/CONTRACT.md): `/api/v1/artifacts[/{id}[/versions]]`, `artifact-jobs`, `artifact-reviews`, `publications/requests`; immutable versions, CAS head (409), provenance carries agent, host, session, mission, job. Context ids (`session_id, mission_id, host_id`) are "never guessed from titles/dirs/hostname". Use for artifact/review lineage nodes; read-only.
- Control-plane ingest (cp-feed `emit.js`): host / mission / session entities with started/updated/terminated verbs (`session.started`, `mission.created/completed` strings seen in `control_plane`). A natural place for a new agent-activity event kind rather than a new bus. Rooms: no first-class Room object found in Herdr itself; Rooms live in the collab layer (`collab-team-rooms.js`, ADR-0007 in herdr-engineering). Verify in discovery A.
- Powerpack manifest pattern: `[[build]]` bootstrap script, `[[startup]]` light reconcile, `[[actions]]` doctor/status, `[[panes]]` board pane. Copy this shape for the optional extension.

## 4. Visual references and licensing

- alexeyw/lot-map: MIT (c) Aleksei Volodin, v0.5.3, TypeScript, pushed 2026-11-12. It is a Claude Code "mod" (`.claude-plugin/plugin.json`, `hooks/register.tsx`, `map.ts` (901 lines), `text.ts`), using Claude Code's mod runtime `$.ui.open/resolve (Box, Text, Svg)`, `$.session.usage()` for context %, `$.store`, `$.clock`, `classic.PreToolUse`-style hooks. Rendering: SVG drawn by React-style components in a Claude pane, pulses flying centre->station, worn spokes, clock hands, 40s route fade, context ring (amber 70%, red 90%), model-switch ring; terminal fallback draws text only (needs >=144 cols). Stations: you, model, memory, files, shell, web, browser, agents, skills, hooks. `PRIVACY.md`: no network, no telemetry. Board type (`types/index.d.ts`): `Entry{id,station,label,from,startedAt,endedAt,status run|ok|err|block,agentId,task,mark}`, `Board{entries,counts,model,step,faults,agents,context,switchedAt}`. MIT permits reuse with copyright notice retained; instruction says do not copy code, so take visual and data-model inspiration only (stations, pulses, ring, wear). Its runtime APIs are Claude-Code-specific and do not apply to Herdr.
- Deemer15/command-mesh: MIT, (c) Aleksei Volodin + Deemer15; explicitly a derivative of Lot Map. JavaScript VS Code/Kiro extension (`extension.js` 981 lines, `map-renderer.js` 731, `futuristic-renderer.js` 191). Rendering: server-side string-built SVG (`<svg viewBox="0 0 900 570">`), no canvas/WebGL; dashboard polls `/state` about every 800 ms; local `http.createServer` on 127.0.0.1 random port, no auth. Collection: hook scripts append to `.kiro/command-mesh/state.json` (last 80 events + per-station counts), plus tailing provider logs: `~/.codex/sessions/**/*.jsonl`, `~/.copilot/session-state/*/events.jsonl`, `~/.kiro/sessions/*/*/messages.jsonl` (credits/model). Multi-provider cores with separate model name, event share, working/idle/offline. Useful design ideas: per-provider core, activity bars stacked by agent, KPIs + timeline + event inspector. Same licensing stance: inspiration only; its auth-less local server is an anti-pattern for us.
- Both use SVG, not canvas. For ours: terminal pane = text/Unicode (and optionally kitty/sixel "pane graphics" exist in Herdr, see socket-api "Pane graphics", unverified); web = SVG or canvas with `prefers-reduced-motion` honoured.

## 5. Harness hook / structured-event APIs for observing sessions

- Herdr (provider-neutral, preferred): `pane.agent_status_changed` (idle/working/blocked/done/unknown), `agent_session` ref, `pane.report_metadata tokens` for model/ctx. Gives liveness for every supported harness with zero per-harness code.
- Pi: extension API `pi.on(...)` observed in pi-engineering `extensions/index.ts`: `session_start, session_shutdown, before_agent_start, agent_start, message_start, message_update, message_end, tool_execution_start/update/end, model_select, before_provider_request, after_provider_response`; `ctx.getContextUsage()` (null right after compaction); `pi.registerCommand/registerTool`. Pi extensions installed via `pi install <path>`. Herdr pi integration v9 lives at `~/.pi/agent/extensions/herdr-agent-state.ts`. Model switch = `model_select`; context = `getContextUsage()`.
- Claude Code: settings hooks present locally: `SessionStart, UserPromptSubmit, PostToolUse, SubagentStart, PreCompact, Stop` (others exist: PreToolUse, SubagentStop, Notification; not verified here). Hook stdin JSON carries `session_id`, `transcript_path`, tool name/input. Model and context % are NOT in hook payloads; lot-map gets them via mod API (`$.session.usage()`), otherwise parse `transcript_path` JSONL (unverified). Herdr's hook only does `session`.
- Codex: `~/.codex/hooks.json` (only `SessionStart` configured, feature `hooks = true` in config.toml), `notify = [...]` turn-ended program, rollout logs at `~/.codex/sessions/**/*.jsonl` (command-mesh tails these), OTel exporter exists upstream (unverified).
- OpenCode: plugin `~/.config/opencode/plugins/herdr-agent-state.js` (v12); Hermes plugin v5.

## 6. Reuse plan (what Agent Operations should take)

1. Event source: Herdr `[[events]]` hooks + `events.subscribe` (state), `pane.report_metadata` tokens (model, ctx, room, task) written by per-harness reporters. Forward to control plane via existing `herdr.cp-feed` ingest, add event kind rather than a new bus.
2. Terminal: a `[[panes]]` entrypoint (placement tab/split) in a Powerpack-style plugin; Unicode renderer, subscribe over socket, reconcile via `session.snapshot` on `events_lost`.
3. Web: new view in `herdr-engineering/packages` using existing `refresh-bus.js`, `motion.js`, design system, `topology-view.js`/`team-map-view.js` as base.
4. Handoff edges from handoff-v2 states; artifact/review lineage from registry provenance.
5. Visuals: lot-map/command-mesh concepts only; if any code is ever copied, keep MIT notices (not planned).
