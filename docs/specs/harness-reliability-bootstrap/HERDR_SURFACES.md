## 3. Naming conventions
- Python modules and functions are `snake_case`, private helpers prefixed `_`: `graph_ingest.py`, `def mission_timeline` (`repo.py:2901`), `def _resolve_mission_key` (`repo.py:391`).
- Generated ids: `def new_id(kind)` (`ids.py:39`) returns `f"{kind}_{suffix}"` (`ids.py:48`) over Crockford base32 (`ids.py:15`); `is_valid_id` checks the `kind_` prefix (`ids.py:51`).
- Mission keys are namespaced, not generated: `_session_mission_identity` → `"mission_key": mission_id if source == "herdr" else f"{source}:{mission_id}"` (`repo.py:97`); producers may not reuse the reserved prefix — `if ":" in source or source == "herdr-ws":` (`ids.py:32`), raw ids may not contain `:` (`ids.py:35`). The herdr plugin supplies it itself: `const WS_PREFIX = "herdr-ws:"` (`emit.js:38`).
- Stage vocabulary is a closed snake_case set: `_STAGES = {` (`repo.py:77`) with `"planning", "specification", "ready", "implementation", "testing", "review", "repair", "validation", "pr", "complete", "failed", "cancelled"` (`repo.py:78-80`).
- Two event-type vocabularies coexist: dotted-lowercase on the wire (`event_type != "mission_activity.snapshot"` `ingest.py:555`; `'mission_activity.snapshot'` `mission_activity_feed.py:370`) and CamelCase inside the projection (`"MissionCreated"` `repo.py:372`, `"MissionStageChanged"` `repo.py:460`, `"SummaryReportFailed"` `control_plane/summary_report.py:23`).
- Ingest payload casing is snake_case: `host_id: host` (`emit.js:162`), `mission_id: missionId(ws)` (`emit.js:165`), `agent_role: role ?? ""` (`emit.js:166`).
- camelCase appears only inside the Pi activity snapshot contract, gated by allowlists: `FIELDS = set('''progress approximatePercent …` (`mission_activity_feed.py:41`) and the store's `WORKER_SUMMARY_FIELDS = frozenset((` `'workerId', 'taskId', 'health', 'state', …` (`control_plane/mission_activity.py:56-59`). Boundary: camelCase lives in `payload.activity` of a `mission_activity.snapshot`; everything else on `/api/v1/ingest` is snake_case. Recovery-plan JSON is camelCase too (`entry["errorCode"] = error_code(error)` `pi_recovery.py:465`) and never crosses `/api/v1`.
- Mission-activity keys are forced to the pi namespace: `_MISSION_KEY = re.compile(r'^pi:[A-Za-z0-9_.-]{1,128}$')` (`control_plane/mission_activity.py:36`), matching `'entity_id': f'pi:{mid}'` (`mission_activity_feed.py:369`).

## 4. Existing error signals
- Stable codes exist for recovery only: `def error_code(error)` (`pi_recovery.py:55`) maps messages/`TimeoutError`/`ConnectionError` to codes (`pi_recovery.py:56-75`), and `EvidenceError` carries `self.code` (`pi_recovery.py:52`).
- `errorCode` is written to the recovery plan JSON (`pi_recovery.py:465`; `pi_recovery_verification.py:247` `"errorCode": error_code(error)`) and `plan["verificationSummary"]` (`pi_recovery_verification.py:253`). It reaches the **CLI** (`from .pi_recovery import RecoveryStore` `cli.py:1572`) and **not** the API — `pi_recovery` is imported nowhere in `control_plane/api.py` (grep, 0 hits): stops at the plan file, never a timeline row.
- Retry/attempt fields that already exist: `job["attempts"] += 1` (`review_gate/queue.py:110`), claim payload key `"attempt"` (`review_gate/worker.py:60`), `"attempt": attempt` (`control_plane/summary_fix.py:360`), recovery journal `"attempts": {}` + `nextEligibleAt` (`pi_recovery.py:104`, written `pi_recovery.py:680`), and action ladder `ACTIONS = ("retry", "restart", "rollback", "none")` (`control_plane/deployment_diagnosis.py:70`). None is a mission-timeline field.
- Pi-side retry vocabulary is allowlisted but only as text inside the activity blob: `attempt maxAttempts nextAction nextActionAt recoveryAttempt` (`mission_activity_feed.py:49`) and `retryAt retryInMs waitMs` (`mission_activity_feed.py:51`).
- `ReportError` (`herdr_engineering/summary_report.py:47`) carries `.code`; at the control plane it becomes `ReportRefused(422, "not a session summary", reason=exc.code)` (`control_plane/summary_report.py:225`) and is returned to the caller by `except ReportRefused as exc: return self._json(exc.body, exc.status)` (`api.py:4300-4301`) — **reaches the API as an HTTP body**; the async path instead records `SummaryReportFailed` with `{"error": exc.code, "detail": …}` (`control_plane/summary_report.py:292`), a **session** event, not a mission timeline item.
- `PublicationRejected(ValueError)` (`mission_activity_feed.py:234`) keeps only fixed codes — `'out_of_order', 'observation_too_old', 'owner_conflict', 'snapshot_regression'` (`mission_activity_feed.py:239-240`); `_record_error` counts them into `result['reasons']` (`mission_activity_feed.py:248`) and `run_once` returns that result (`mission_activity_feed.py:426-427`) which is printed to host stdout (`print(json.dumps(result))` `mission_activity_feed.py:523`) — **stops at the host log**.
- The same reason codes do reach the ingest response: `{'accepted': False, 'reason': 'observation_too_old'}` (`control_plane/mission_activity.py:224`), `'out_of_order'` (`:249`), `'owner_conflict'` (`:253`), `'snapshot_regression'` (`:256`), returned through `{"entity_type": entity_type, "entity_id": entity_id, **result}` (`ingest.py:558`) — response only, never an event.
- `GitHubAuthError(RuntimeError)` (`github_auth.py:121`) is always translated before the API: `raise GitHubAppError("rate_limited", retry_at=…)` (`review_gate/github_app.py:230-231`), `raise self._fail(exc.reason)` (`control_plane/intel_github.py:72`). A leak would hit the generic handler `except Exception as exc` → `{"error": message}` with `"GitHub service is unavailable."` for `resource == "github"` (`api.py:3150-3157`) — HTTP only, no timeline row.
- `CheckpointError(RuntimeError)` (`checkpoint.py:20`) is raised/caught only inside `checkpoint.py` and is referenced elsewhere only by its own tests (`tests/test_checkpoint_resume.py`, `tests/test_checkpoint_store_safety.py`) — nothing in `control_plane/` imports it (grep); whether the harness surfaces it: needs verification at integration time.
- Boundary note: `except ValueError as exc` → 400 `{"error": message}` (`api.py:3117-3121`), but ingest failures are deliberately flattened — `logging.getLogger(__name__).exception("ingest failed")` then `self._send_json(500, {"error": "ingest failed"})` (`api.py:3152-3155`), so a rejected harness envelope is a 500 plus a log line with no machine code.

## Reusable as-is

- `herdr-timeline` / `renderTimeline` (`herdr-web-components/index.js:18`, `timeline.js:28`) — pure, `items`-driven, already fed by `client.missionTimeline` (`app.js:617`).
- `_with_collab_tasks` (`api.py:1905`) — the proven pattern for grafting an extra `kind` onto a timeline and failing open (`api.py:1931-1932`).
- `POST /api/v1/ingest` envelope contract + `INGEST_ENTITY_TYPES` self-description (`api.py:4376`, `api.py:3821`) — one producer path, batched to 64 (`api.py:4382`).
- `emit.js` envelope builders (`emit.js:130`, `emit.js:140`, `emit.js:155`) and `createSnapshotPublisher` body-dedupe (`snapshot.js:178`) — copyable producer skeleton.
- `readHostJson` / `loadHostConfig` (`host-config.js:30`, `host-config.js:79`) and `createGitMetadataReader` (`git-metadata.js:42`) — host URL/token and repo identity, no new config format needed.
- Mission-activity freshness (`mission_activity.py:275-278`, `repo.py:412`) — an existing staleness signal a harness row can reuse instead of inventing one.

## Missing for harness telemetry
- Per-attempt retry budget / circuit / replay-safety decisions: no ingest entity, no timeline `kind`, no route (`repo.py:2910-2948` enumerates stage/test/review/PR/merge only).
- Sanitized error fingerprints: the only stable codes are recovery-local (`pi_recovery.py:55`) and never reach `/api/v1` (§4).
- Incident evidence bundles: no artifact kind or event type is accepted for them; failures that are surfaced end up as HTTP bodies or host-side stdout (`api.py:3150-3157`, `mission_activity_feed.py:523`).
- Resolution verdicts: `mission-outcomes` has its own route (`api.py:3466`) but no timeline item, so a verdict cannot be seen in the same view as the stages.
- Worker-level telemetry: `Worker` carries `worker_id`/`status` (`pi_autospec.py:15-18`) but no retry, and `pi_autospec` is unwired (§5); `workerDetails` is trimmed to health/state/model/route (`mission_activity.py:56-59`).
- Machine-readable ingest failure: 500 `{"error": "ingest failed"}` (`api.py:3155`) is the only signal a harness producer gets on rejection.
- pi-side module names for the above live in the pi harness repo, not this checkout: names per the H01 brief (retry budget, circuit, replay-safety, error fingerprint, evidence bundle, resolution verdict); **needs verification at integration time**.
